# 공공데이터 API 확인 결과

> 상태: 실제 응답으로 확인한 항목과 미확인 항목을 구분한다. 미확인 항목은 `(미검증)`으로 표시한다.
> 키는 이 문서와 샘플에 포함하지 않는다.

## OA-15994 승강기 가동현황 (Issue #9)

### 1. 호출 방식
- 엔드포인트: `http://openapi.seoul.go.kr:8088/{KEY}/json/SeoulMetroFaciInfo/{시작}/{끝}/`
- 서비스명 `SeoulMetroFaciInfo`는 호출로 확인했다. 이름은 로컬 CSV 파일명과 같다.
- 한 번에 최대 1,000건을 받는다. 전체 2,809건을 3번 호출해서 모두 받았다(결과 코드 3회 모두 `INFO-000`).
- 샘플: `docs/samples/OA-15994_SeoulMetroFaciInfo_2026-11-13.json` (전체 2,809건, 키 없음)

### 2. 응답 구조
- 최상위 키: `SeoulMetroFaciInfo`
- 하위 키: `list_total_count`(전체 건수), `RESULT`(`CODE`, `MESSAGE`), `row`(배열)
- 결과 코드 정상: `INFO-000` / `정상 처리되었습니다`

### 3. 필드 (확인됨)
| 필드 | 예시 | 비고 |
|---|---|---|
| STN_CD | 0150 | 4자리 역 코드. 273~274개 역 |
| STN_NM | 서울역(1) | 역명. 괄호 숫자가 노선 번호인 경우가 있다 |
| ELVTR_NM | 승강기)엘리베이터-서울(1)역 섬식(상) 5-1 내부#1 | 설비명. 방면·상하행 텍스트가 섞여 있다 |
| OPR_SEC | B2-B1 | 운행 층 구간 |
| INSTL_PSTN | 시청 방면5-1,남영 방면6-4 | 설치 위치 설명. 방면 텍스트가 들어 있다 |
| USE_YN | 사용가능 / 보수중 | 상태 값. 2종류만 확인됨 |
| ELVTR_SE | EV / ES / WL / MW | 설비 종류. EV=엘리베이터 |

- 필드 7개 모두 문자열이다.
- 설비 고유 ID 필드는 없다(확인됨). 중복 키 (STN_CD, ELVTR_NM)는 2,809건 중 0건이다.

### 4. 설비 종류 (확인됨, 2,809건 기준)
- EV(엘리베이터): 866건, 273개 역
- ES(에스컬레이터): 1,884건
- WL(휠체어리프트): 41건
- MW(무빙워크): 18건
- 엘리베이터 모델에는 EV만 넣는다.

### 5. 상태 표현 (확인됨)
- `USE_YN` 값은 `사용가능`, `보수중` 두 가지뿐이다.
- 실제 응답(2026-11-13 호출 시점): 전체 사용가능 2,680 / 보수중 129. EV 기준 사용가능 845 / 보수중 21.
- `고장`, `점검` 같은 별도 상태 값은 확인되지 않았다.
- 정상 설비도 응답에 포함된다(사용가능 2,680건).
- 보수중 → 가동 안됨, 사용가능 → 가동중으로 매핑한다(DB 값 기준, 결정 사항).

### 6. 갱신 시각 (미확인: 원본 시각 없음)
- 응답 본문에는 갱신 시각 필드가 없다(확인됨).
- HTTP `Date` 헤더만 있다. 이는 서버 응답 시각이지 데이터 갱신 시각이 아니다.
- 데이터 갱신 주기는 "매시"로 알려져 있다(공공데이터 포털 설명, 응답으로는 미검증).
- 로컬 CSV(2026-11-12 작성 파일)와 비교하면 같은 2,809건 중 **100건의 `USE_YN`이 바뀌었다**(사용가능→보수중 85건, 보수중→사용가능 15건). 상태가 시간에 따라 변한다는 뜻이다.
- 결론: `observed_at`은 원본에 없으므로 NULL이다. TTL 기준은 `fetched_at`이다. 2시간 TTL은 매시 갱신 기준의 추정이며 (미검증).

### 7. 역 코드와 역명
- 역 코드 STN_CD는 274개(설비가 있는 역 273개)다. 동묘앞은 `0159`다.
- 같은 역명이 여러 노선에 있는 경우 역명 끝에 `(n)`으로 노선 번호가 붙는다(예: `서울역(1)`, `동묘앞(1)`).
- 괄호가 없는 역명도 많다(예: `종각`, `강동`). 이 경우 노선은 이 API로 확인할 수 없다.

### 8. 호선 범위 (부분 확인, 미검증)
- EV 설비의 역명 괄호 번호는 1~8만 나타났다(9호선 번호 없음).
- 하지만 EV 866건 중 550건은 역명에 괄호 번호가 없어서 노선을 판정할 수 없다.
- 노선 컬럼이 없으므로 1~8호선 범위는 **미검증**이다. 노선 매핑은 T13(역·노선 원본)에서 해야 한다.

### 9. 위치 설명
- `INSTL_PSTN`과 `ELVTR_NM`에 방면과 출입구 정보가 있다(예: `시청 방면5-1`, `4번 출입구`).
- 방면은 상·하행으로 나누지 않고 원문 그대로 저장한다(결정 사항).
- 방면 뒤 번호(예: 5-1)의 의미는 미검증이다.

### 10. 로컬 CSV와의 차이
- 같은 키 2,809개가 모두 일치한다. 차이는 `USE_YN` 100건뿐이다.
- 즉 API는 실시간 상태를 준다. 로컬 CSV는 2026-11-12 시점 스냅샷이다.

### 11. 미확인 항목 (미검증)
- 갱신 주기 "매시"의 실제 동작(응답으로 확인 불가)
- 원본 갱신 시각 필드 존재 여부(응답에 없음)
- 1~8호선 전체 범위와 정상 설비 전부 포함 여부(노선 컬럼 없음)
- 호출 제한(일일 한도)과 응답 시간의 정확한 기준(미측정)
- 역명과 노선의 다대다 관계(역 원본 데이터 T13에서 확인)
