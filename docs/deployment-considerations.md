# 배포 조건 정리

> **결정(2026-11-14): 시연 서버는 집 데스크탑에서 터미널로 직접 실행한다.** 실행·준비 순서는 README "시연 서버 실행"을 본다. 이 문서는 현재 구조(FastAPI + SQLite 파일)의 조건을 정리한다. 나중에 호스팅으로 옮길 때 아래 조건을 쓴다. Docker, Redis, PostgreSQL은 MVP 규칙상 도입하지 않는다(Issue #45).
>
> **데스크탑 서버의 제약:** PC가 꺼지거나 절전에 들어가면 서버가 멈춘다(시연 중 절전 해제). 역·경로 API는 공개 읽기 API이며, 소셜 로그인·계정 변경에는 별도 인증을 적용한다. 외부 공개에는 HTTPS 등 아래 배포 조건이 필요하다. SQLite 영속성은 PC의 디스크가 맡고, 백업은 변경 전에 파일을 복사해 둔다. 실제 OAuth의 HTTP 개발은 루프백에서만 허용한다.

## 1. 호스팅이 충족해야 할 조건

| 항목 | 조건 | 이유 |
|---|---|---|
| Python | 3.13, `uv sync`로 의존성 설치 | `pyproject.toml` |
| 프로세스 | 상주하는 프로세스 1개. 시작 명령 예: `uvicorn app.main:app --host <주소> --port <포트>` | 서버리스처럼 요청마다 프로세스가 사라지면 메모리 캐시(도착 정보)가 유지되지 않고 SQLite 파일도 문제가 된다 |
| 파일 시스템 | **쓰기 가능하고 재시작·재배포 후에도 남는 디스크** | SQLite는 파일 하나다. 임시 디스크면 재시작 때 데이터가 사라진다 |
| 인스턴스 수 | 1개 | SQLite 파일을 여러 인스턴스가 나눠 쓰는 구성은 지원하지 않는다 |
| 외부 연결 | 소셜 로그인은 Google·카카오의 HTTPS 토큰/사용자 정보 API 연결 필요. 엘리베이터 수집은 서울 열린데이터광장 연결 필요 | OAuth는 요청 중 교환하며, 공공데이터는 CLI로 수집한다 |

## 2. SQLite 영속성과 백업

계정 추가 이후 SQLite에는 사용자·즐겨찾기·활성 세션·일회용 OAuth 흐름도 저장된다. `AUTH_PUBLIC_BASE_URL`, `AUTH_FRONTEND_URL`, 제공자 키·시크릿, `AUTH_COOKIE_SECURE=true`, 명시적인 CORS Origin을 설정하고 제공자 콘솔의 Redirect URI를 정확히 맞춘다. FE/BE는 SameSite=Lax 쿠키를 사용할 수 있는 같은 사이트에 배치한다. OAuth 코드·쿠키가 남지 않도록 서버·프록시의 인증 접근 로그를 비활성화하거나 민감 필드를 제거한다. 설정값과 실행 절차는 [README](../README.md#google카카오-로그인-준비)를 따른다.

- DB 경로는 `DATABASE_URL`(예: `sqlite:////절대/경로/app.db`)로 정한다. 영속 디스크 위의 절대 경로를 쓴다.
- 스키마는 `alembic upgrade head`로 만든다. 서버 시작이 자동으로 마이그레이션하지는 않는다.
- 데이터 적재 순서(역 시드, 간선, 엘리베이터 수집)는 README를 따른다. **실제 DB 적재는 별도 승인 사항이다.**
- 백업: 서버를 멈춘 상태에서 파일을 복사하거나, `sqlite3 <db> ".backup <대상>"`을 쓴다. 쓰는 중에 `cp`로 복사하지 않는다. 적재·마이그레이션 전에는 반드시 백업한다.
- 시연용이라면 데모 DB(`app.cli.build_demo_db`)를 영속 디스크에 두는 방법이 있다. 단 출력 위치가 임시 디렉터리로 제한되어 있어 빌드 후 복사해야 한다. 이 경우 샘플 엘리베이터는 항상 "정보 없음"으로 보인다.
- 결정 필요: 백업 주기와 보관 위치, 복구 절차 담당자.

## 3. HTTPS

- 이 앱은 TLS를 직접 처리하지 않는다. HTTPS는 호스팅의 종단 처리나 앞단 프록시가 맡는다.
- FE가 HTTPS 페이지에서 호출하면 Backend도 HTTPS여야 한다(혼합 콘텐츠 차단).
- 서울 열린데이터광장 호출은 HTTP(8088)만 확인했고 클라이언트는 평문 HTTP를 기본 허용한다(2026-11-14 결정). 키가 평문으로 나가므로 키는 시연 PC의 `.env`에만 두고, 수집은 CLI로만 실행한다(서버 프로세스는 외부 API를 호출하지 않는다).

## 4. 환경 변수

| 변수 | 필수 | 설명 |
|---|---|---|
| `DATABASE_URL` | 예 | 기본값 `sqlite:///./data/dev.db`(상대 경로, 로컬 개발용). 배포에서는 영속 디스크의 절대 경로로 지정 |
| `CORS_ALLOWED_ORIGINS` | FE가 브라우저로 호출하면 예 | FE Origin을 쉼표로 명시. 기본은 빈 값(교차 출처 불허). 와일드카드 불가 |
| `SEOUL_OPEN_API_KEY` | 수집을 쓸 때만 | 서버 실행에는 불필요. 값을 저장소·로그·채팅에 남기지 않는다 |
| `ELEVATOR_STATUS_TTL_MINUTES` | 아니오 | 기본 120(임시) |
| `ELEVATOR_AUTO_REFRESH` | 아니오 | 기본 false. true는 실제 수집 CLI의 정기 적재 활성화. 단일 서버에서만 설정 |
| `ELEVATOR_REFRESH_INTERVAL_MINUTES` | 아니오 | 기본 30, 1~60. 자동 수집 활성화 시 TTL보다 짧아야 함. 실패 재시도는 1분부터 지수 백오프 |
| `ARRIVAL_CACHE_TTL_SECONDS` | 아니오 | 기본 30 |
| `ALTERNATIVE_SEARCH_DEPTH`, `WALK_TO_STATION_MINUTES`, `STATION_ENTRY_MINUTES`, `EXIT_WALK_MINUTES`, `ROUTE_SEGMENT_MINUTES`(2), `ROUTE_TRANSFER_MINUTES`(5) | 아니오 | 검증되지 않은 추정 기본값 |

- `.env`는 저장소에 올리지 않는다(`.gitignore`). 호스팅의 환경 변수 설정 기능으로 주입하는 방식을 권한다.
- 환경 변수가 `.env`보다 우선한다.

장시간 실행 권장 명령은 `uv run python -m app.cli.serve --port 8000`이다. 포트 확보와 DB 스키마 점검 후 실행하며, `--refresh-elevators`를 명시하면 시작 직후와 이후 주기적으로 별도 CLI 프로세스를 실행한다. 외부 수집은 요청 처리 중 실행하지 않는다. 성공 여부는 수집기 로그와 `GET /ready`의 최신/오래된 건수로 확인한다. `/health`는 기존처럼 DB와 무관한 생존 점검이다. 자동 수집은 수동 CLI를 정기 실행하는 선택 기능이며 실제 API 호출·DB 적재는 운영자가 활성화한다. SQLite 쓰기 잠금은 최대 30초 기다린다. 실제 서버에서 자동 수집·절전 복귀는 아직 검증하지 않았다.

## 5. 팀이 결정해야 할 사항

결정 완료(2026-11-14)
- 호스팅 대상: 집 데스크탑, 터미널 실행.
- 인접 간선: 시간표(OA-101)에서 추출해 저장한다(공식 근거 없음, 응답에 표시).
- 수집: 시연 PC에서 CLI를 수동 실행한다. 평문 HTTP 허용.

남은 확인
1. FE Origin 목록(`CORS_ALLOWED_ORIGINS`)과 FE를 어느 PC에서 여는지.
2. 수집 호출 한도(OA-15994, OA-101 일일 한도 미확인).
3. 접근 제어: 역·경로 조회는 공개 읽기 API다. 새 계정 변경 API는 세션·Origin·CSRF를 검증하며, 외부 공개는 HTTPS 등 배포 조건을 갖춘 뒤 진행한다.

## 6. 확인하지 않은 것

- 어떤 호스팅에서도 실제로 배포해 보지 않았다. 위 조건은 코드 구조에서 도출한 것이다.
- 호출 한도, 동시 접속 성능은 측정하지 않았다.
