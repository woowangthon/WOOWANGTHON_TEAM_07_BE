# 배포 조건 정리 (결정 전)

> **배포 대상은 정해지지 않았다.** 이 문서는 현재 구조(FastAPI + SQLite 파일)에서 어떤 호스팅이든 충족해야 하는 조건과, 팀이 결정해야 할 항목만 정리한다. 특정 서비스를 권하지 않는다. Docker, Redis, PostgreSQL은 MVP 규칙상 도입하지 않는다(Issue #45).

## 1. 호스팅이 충족해야 할 조건

| 항목 | 조건 | 이유 |
|---|---|---|
| Python | 3.13, `uv sync`로 의존성 설치 | `pyproject.toml` |
| 프로세스 | 상주하는 프로세스 1개. 시작 명령 예: `uvicorn app.main:app --host <주소> --port <포트>` | 서버리스처럼 요청마다 프로세스가 사라지면 메모리 캐시(도착 정보)가 유지되지 않고 SQLite 파일도 문제가 된다 |
| 파일 시스템 | **쓰기 가능하고 재시작·재배포 후에도 남는 디스크** | SQLite는 파일 하나다. 임시 디스크면 재시작 때 데이터가 사라진다 |
| 인스턴스 수 | 1개 | SQLite 파일을 여러 인스턴스가 나눠 쓰는 구성은 지원하지 않는다 |
| 외부 연결 | 지금은 없음. 엘리베이터 수집을 켜면 서울 열린데이터광장으로 나가는 연결 필요 | 서버는 외부 API를 호출하지 않는다 |

## 2. SQLite 영속성과 백업

- DB 경로는 `DATABASE_URL`(예: `sqlite:////절대/경로/app.db`)로 정한다. 영속 디스크 위의 절대 경로를 쓴다.
- 스키마는 `alembic upgrade head`로 만든다. 서버 시작이 자동으로 마이그레이션하지는 않는다.
- 데이터 적재 순서(역 시드, 간선, 엘리베이터 수집)는 README를 따른다. **실제 DB 적재는 별도 승인 사항이다.**
- 백업: 서버를 멈춘 상태에서 파일을 복사하거나, `sqlite3 <db> ".backup <대상>"`을 쓴다. 쓰는 중에 `cp`로 복사하지 않는다. 적재·마이그레이션 전에는 반드시 백업한다.
- 시연용이라면 데모 DB(`app.cli.build_demo_db`)를 영속 디스크에 두는 방법이 있다. 단 출력 위치가 임시 디렉터리로 제한되어 있어 빌드 후 복사해야 한다. 이 경우 샘플 엘리베이터는 항상 "정보 없음"으로 보인다.
- 결정 필요: 백업 주기와 보관 위치, 복구 절차 담당자.

## 3. HTTPS

- 이 앱은 TLS를 직접 처리하지 않는다. HTTPS는 호스팅의 종단 처리나 앞단 프록시가 맡는다.
- FE가 HTTPS 페이지에서 호출하면 Backend도 HTTPS여야 한다(혼합 콘텐츠 차단).
- 서울 열린데이터광장 호출은 현재 HTTP(8088)만 확인했고 클라이언트는 평문 HTTP를 기본으로 막는다. 키가 평문으로 나가므로 HTTPS 주소 확인 전에는 서버에서 수집을 켜지 않는다.

## 4. 환경 변수

| 변수 | 필수 | 설명 |
|---|---|---|
| `DATABASE_URL` | 예 | 기본값 `sqlite:///./data/dev.db`(상대 경로, 로컬 개발용). 배포에서는 영속 디스크의 절대 경로로 지정 |
| `CORS_ALLOWED_ORIGINS` | FE가 브라우저로 호출하면 예 | FE Origin을 쉼표로 명시. 기본은 빈 값(교차 출처 불허). 와일드카드 불가 |
| `SEOUL_OPEN_API_KEY` | 수집을 쓸 때만 | 서버 실행에는 불필요. 값을 저장소·로그·채팅에 남기지 않는다 |
| `ELEVATOR_STATUS_TTL_MINUTES` | 아니오 | 기본 120(임시) |
| `ARRIVAL_CACHE_TTL_SECONDS` | 아니오 | 기본 30 |
| `ALTERNATIVE_SEARCH_DEPTH`, `WALK_TO_STATION_MINUTES`, `STATION_ENTRY_MINUTES`, `EXIT_WALK_MINUTES` | 아니오 | 검증되지 않은 추정 기본값 |

- `.env`는 저장소에 올리지 않는다(`.gitignore`). 호스팅의 환경 변수 설정 기능으로 주입하는 방식을 권한다.
- 환경 변수가 `.env`보다 우선한다.

## 5. 팀이 결정해야 할 사항

1. 호스팅 대상(영속 디스크를 지원하고 상주 프로세스를 돌릴 수 있는 곳). 비용·계정 소유자 포함.
2. 공개 도메인과 HTTPS 방식, FE Origin 목록.
3. 시연에 쓸 DB: 데모 DB 그대로 / 실제 데이터 적재(백업과 승인 필요). 실제 적재 시 인접역 간선(PROVISIONAL)을 쓸지(운영 경로는 기본 차단).
4. 백업 주기와 복구 담당.
5. 엘리베이터 수집을 시연 환경에서 돌릴지(HTTPS 확인, 호출 한도 확인 필요).
6. 접근 제어: 현재 인증이 없다. 공개 URL이면 누구나 읽기·계산 API를 호출할 수 있다(쓰기 API는 없다).

## 6. 확인하지 않은 것

- 어떤 호스팅에서도 실제로 배포해 보지 않았다. 위 조건은 코드 구조에서 도출한 것이다.
- 호출 한도, 동시 접속 성능은 측정하지 않았다.
