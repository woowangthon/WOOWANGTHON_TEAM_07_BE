# 역·노선 시드 출처와 커버리지

> 이 시드는 **1~8호선 전체를 확보했다는 뜻이 아니다.** 아래 커버리지를 반드시 함께 읽는다.
> 확인되지 않은 항목은 `(미검증)`으로 표시한다.

## 파일

| 파일 | 내용 |
|---|---|
| `stations_oa12035.csv` | OA-12035의 1~8호선 276행. 코드는 4자리 0 패딩 문자열, 역명은 앞뒤 공백만 제거 |
| `external_code_links.csv` | OA-15994 `STN_CD` 중 OA-12035 역번호와 일치가 확인된 274개 |
| `station_review.csv` | REVIEW 목록 (환승 그룹, 역명 차이). 공식 근거가 확인된 환승 그룹만 `CONFIRMED` |
| `transfer_evidence_oa13290.csv` | `CONFIRMED` 그룹마다 공식 환승 기록(방향별 한 행, 76행) |
| `manifest.json` | 출처, 해시, 행 수, 커버리지 (기계가 읽는 형식) |

파일은 `scripts/build_station_seed.py`로 원본 CSV에서 다시 만들 수 있다. 원본 CSV는 저장소에 두지 않고 SHA-256만 `manifest.json`에 기록한다.

## 출처

- **데이터셋:** 서울교통공사_역주소 및 전화번호 (OA-12035)
- **URL:** https://data.seoul.go.kr/dataList/OA-12035/S/1/datasetView.do
- **원본 파일:** `서울교통공사_역주소 및 전화번호_20250318.csv` (CP949, 289행, 2025.03.31 수정)
- **내려받은 날:** 2026-11-13
- **기준일 (미확정):** 페이지 본문은 "2025년 8월 기준"이고, 최신 파일명은 20250318이며, 검색 결과에는 2026년 2월 기준 표기도 있다. 서로 일치하지 않는다.
- **이용 조건:** 공공누리 1유형(출처표시, 상업적 이용·변경 가능)으로 표시되어 있다. 페이지 표기를 옮긴 것이며 원문과 대조하지 않았다 (미검증).
- **operator:** `station_lines.operator = 서울교통공사`는 이 출처 범위의 행에만 설정한다. `lines.operator`는 비워 둔다.

## 커버리지

| 노선 | 행 수 | 상태 |
|---|---|---|
| 1호선 | 10 | **PARTIAL.** 일부 구간만 확보. 나머지 구간은 별도 조사 대상이며 미확보다 |
| 2~8호선 | 50 / 34 / 26 / 56 / 39 / 42 / 19 | 행 수를 공식 역 수와 대조하지 않았다 (미검증) |

- 1호선 10개 역이 서울교통공사 관할 구간이라는 설명은 추정이며 공식 근거로 확인하지 않았다 (미검증).
- API 응답은 1호선 역이 포함될 때 `limitations`에 일부 구간만 포함됨을 알린다 (`docs/api-contract.md` 0.4절).

## 코드 관계

- OA-12035 `역번호`는 **노선별 코드**다. 예: 서울역 1호선 `0150`, 4호선 `0426`.
- 원본 `역번호`는 앞의 0이 없다(`150`). `STN_CD` 형식에 맞춰 4자리로 패딩한다.
- OA-15994 `STN_CD` 274개는 모두 OA-12035 역번호와 일치했다(2026-11-13 샘플 기준). 이 일치를 근거로 같은 코드를 같은 노선 행에 연결한다.
- 시드에 있지만 OA-15994에 설비가 없는 코드: `0321` 충무로(3호선), `2538` 청구(5호선). 연결하지 않는다.
- OA-101 `STATION_CD`는 3개 역(0150, 0159, 0222)만 확인했다. 전체 대조 전까지 연결하지 않는다 (미검증).
- OA-101 `FR_CODE`는 역번호와 다른 체계다(서울역 133). 매핑에 쓰지 않는다.

## REVIEW 규칙

- 역명이나 지번주소가 같다는 이유만으로 서로 다른 노선의 역을 병합하지 않는다. 지번주소는 환승 여부의 근거가 되지 않는다(실제 환승역도 주소가 다르다).
- 환승 그룹(`TRANSFER_CANDIDATE`)은 공식 환승 기록으로 확인된 그룹만 `CONFIRMED`이고, 나머지는 `PENDING`이다. 현재 `CONFIRMED` 34개, `PENDING` 0개다. 확정 근거와 규칙은 아래 "환승 검증"에 있다.
- 이미 별도 역으로 적재된 뒤에 그룹을 `CONFIRMED`로 바꾸면 적재가 충돌로 중단된다. 기존 역을 합치는 절차는 구현되어 있지 않다. 적재 전에 확정하는 것을 권장한다.
- 역명 차이(`NAME_VARIANT`)는 코드 일치를 근거로 `ACCEPTED_BY_CODE`(66건)와 `PENDING`(5건)으로 나눴다. `PENDING` 5건은 표기를 확인하기 전까지 시드의 원본 표기를 그대로 둔다.

## 환승 검증 (공식 근거)

**근거 데이터:** 서울교통공사_환승역거리 소요시간 정보 (OA-13290)

- **URL:** https://data.seoul.go.kr/dataList/OA-13290/S/1/datasetView.do
- **원본 파일:** `서울교통공사_환승역거리 소요시간 정보_20250331.csv` (CP949, 140행). 열: `호선, 환승역명, 환승노선, 환승거리, 환승소요시간`
- **기준일:** 페이지 설명은 "2025.3 기준 자료", 데이터 갱신일 2025.03.31, 갱신주기 연간. 내려받은 날 2026-11-13
- **이용 조건:** 공공누리 1유형으로 검색 결과에 표시되어 있다. 원문과 대조하지 않았다 (미검증)
- **원본 SHA-256, 행 수:** `manifest.json`의 `transfer_source`
- 이 데이터에서 환승 **여부**만 근거로 쓴다. 환승소요시간은 환승거리를 보행속도 1.2m/s로 나눈 추정치라 쓰지 않는다.

**확정 규칙** (`scripts/build_station_seed.py`가 같은 규칙을 코드로 적용한다)

1. 공식 기록 한 행은 "A호선 X역에서 B호선으로 환승"이다. X를 시드의 A호선 역 하나로 찾을 때, 같은 노선 안에서 이름이 정확히 같거나 괄호 부연만 뺀 이름이 같은 역이 **유일**해야 한다.
2. 반대 방향 기록(B호선 Y역에서 A호선으로 환승)이 있어야 하고, 두 기록의 환승거리와 환승소요시간이 같아야 한다.
3. 위 쌍으로 이어지는 역들을 한 그룹으로 보고, 그룹 안의 **모든 쌍**이 확인되고 노선이 서로 달라야 `CONFIRMED`다.
4. 역명이나 주소가 같다는 사실만으로는 확정하지 않는다. 역명은 공식 기록이 가리키는 역을 시드에서 찾는 데만 쓴다.
5. 예외로, 사용자가 승인해 `MANUAL_CONFIRMATIONS`에 명시한 그룹만 수동 확정한다. 일반 규칙이 아니다. 그룹마다 (a) 공식 환승 기록이 양방향으로 있고 거리·시간이 같으며 (b) OA-12035 지번주소에 해당 역명과 노선이 표기되어 있음을 생성 스크립트가 직접 검증하고, 실패하면 생성을 중단한다. 현재 목록은 서울역(`0150|0426`) 하나다.

**결과**

- 환승 그룹 **34개** 확정 (2개 노선 32개, 3개 노선 2개). 모든 쌍이 양방향 공식 기록으로 확인되었다. 이 중 33개는 규칙 1~3으로, 1개(서울역)는 수동 확정이다.
- 역명 동일 후보 33개가 모두 확정되었다(규칙 1~3으로 31개, 확장 교체 1개, 수동 1개).
- 후보에 없던 그룹 2개가 확인되었다. 역명 동일 후보 `0153|0319`는 5호선 `종로3가(탑골공원)`(`2535`)까지 3개 노선으로 확장되었다(`0153|0319|2535`). 4호선 `총신대입구(이수)`와 7호선 `이수`(`0432|2738`)는 역명이 달라 후보에 없었지만 공식 기록으로 확인되었다.
- **서울역(`0150|0426`, 수동 확정):** 시드 역명은 두 코드 모두 `서울`이고 공식 역명은 `서울역`이라 규칙 1로 연결되지 않았다. 사용자가 다음 근거로 확정을 승인했다(2026-11-13). (1) OA-13290에 1호선↔4호선 `서울역` 환승 기록이 양방향으로 있고 거리·시간이 같다(159m, 02:13). (2) OA-12035 지번주소 열에 `서울역(1호선)`, `서울역 (4호선)` 표기가 있다. 증거 파일에는 `name_match=manual`로 기록되어 있다.
- 병합해도 `station_lines`는 276개 그대로이고, `stations`는 276개에서 **240개**가 된다. 외부 코드 행은 550개다(OA-12035 276 + OA-15994 274).

**표시명 (병합 근거가 아니라 표시용)**

- 노선별 표기가 같은 그룹은 그 이름을 쓴다.
- 서울역(`0150|0426`): 사용자 지정 표시명 `서울역`. 시드 원본 역명은 두 코드 모두 `서울`이다.
- 종로3가(`0153|0319|2535`): `종로3가`. 5호선 원본 역명은 `종로3가(탑골공원)`이다.
- 삼각지(`0428|2629`): `삼각지`. 4호선 원본 역명은 `삼각지(전쟁기념관)`이다.
- 총신대입구(이수)(`0432|2738`): 사용자 지정 통합 표시명 `총신대입구(이수)`. 원본은 4호선 `총신대입구(이수)`, 7호선 `이수`다.
- **노선별 원본 이름은 `stations_oa12035.csv`와 `station_review.csv` 비고에 보존된다.** DB의 `stations.station_name`은 통합 표시명 하나만 담고, 노선별 원본 이름 컬럼은 아직 없다(필요하면 별도 결정).

**공식 기록 중 시드로 해석되지 않은 행 (7행)**

- 상대 노선의 역이 시드에 없는 경우: 2호선 신도림, 4호선 창동, 5호선 신길, 7호선 도봉산·가산디지털단지·온수가 1호선으로 환승한다고 되어 있으나 해당 1호선 역이 시드에 없다. 1호선이 일부 구간뿐이라는 단서다.
- 5호선 까치산이 2호선으로 환승한다고 되어 있으나 시드의 2호선에 까치산이 없다. 2호선 지선 일부가 빠졌을 수 있다 (미검증).
- 같은 노선 안의 환승(2호선 성수·신도림, 5호선 강동)은 지선 환승이라 서로 다른 `station_lines` 사이의 환승이 아니며 그룹으로 만들지 않았다.
- 공식 기록에 있는 공항철도, 경의중앙선, 9호선, 분당선 등 1~8호선 밖 노선과의 환승은 범위 밖이다.

**한계**

- 위 34개는 "공식 기록상 이 노선들 사이의 환승이 있고, 각 역이 시드에서 하나로 해석된다"는 뜻이다(서울역은 검증한 수동 확정). 환승 통로나 환승 시간을 검증한 것은 아니다.
- 시드에 없는 역(1호선 다수 등)의 환승은 확인하지 못했다.

## 적재

```bash
uv run alembic upgrade head
uv run python -m app.cli.load_seed --dry-run   # 적용해 본 뒤 롤백
uv run python -m app.cli.load_seed
```

- 외부 API를 호출하지 않는다. 같은 키는 Upsert하고, 재실행해도 행 수와 ID가 변하지 않는다.
- 충돌하면 전체를 롤백한다. 기존 행은 삭제하거나 덮어쓰지 않는다.
- `CONFIRMED` 그룹은 적재할 때 하나의 역으로 합쳐진다. 이미 따로 적재된 DB에서 `PENDING`을 `CONFIRMED`로 바꾸면 충돌로 중단되므로, 환승 그룹은 **첫 적재 전에** 확정한다.
